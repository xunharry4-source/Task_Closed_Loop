# Task Coverage Expansion

这是弱模型的思考角度扩展层。

它不生成任务，不生成任务想法，也不决定最终任务数量。

只有首轮任务经过完整的单任务审查、集合审查后，合格任务少于配置阈值时，才调用本层。阈值只用于判断是否需要再次扩展思考角度，不是最终任务数量目标。

直接读取：

- `resources`
- `reality`
- `open_tasks`
- `capabilities`
- `accepted_tasks_so_far`：已经通过审查的任务
- `rejected_tasks_so_far`：被拒绝的任务及原因

`rejected_tasks_so_far` 记录已经探索但失败的方向、失败阶段（`stage`）、失败原因（`reason`、`structural_findings`）和措辞问题（`wording_problems`）。

本层的目标不是重复首轮，而是找出**首轮没有充分展开的其它独立思考角度**。

对于已经失败的方向：

- 如果失败原因是“核心工作关系价值低、现实不成立、能力不支持”，避免换个说法重复同一方向
- 如果失败原因只是措辞差，不把它误判为“需要一个全新的角度”；该任务会由改写步骤处理
- 如果失败原因是引用格式或引用路径不存在（`structural_findings` 中写明了应该怎样引用），方向本身并未被否定；新角度可以沿用该方向，但必须按引用语法给出真实存在的依据
- 只有能提出实质不同的问题空间、结果目标或现实关系时，才形成新角度

思考角度只能从已经物化的 `resources` / `reality` 出发。可观察能力的“先去读什么状态域”已经由观察类任务层负责，本层不得再把 `capability:<capability_id>` 当成新的思考角度来源。

思考角度可以来自：

- 当前资源中另一种重要关系
- 不同对象之间另一种值得比较的角度
- 可以明显改变用户判断的其它分析维度
- 当前能力可以把资源转化成的另一类高价值结果
- 弱模型首轮容易忽略、但真实数据明确支持的问题空间

输出 `new_angles` 数组，每个角度输出：

- angle_id
- angle
- question_to_answer
- why_valuable
- why_it_is_separate
- based_on_refs
- related_capability_ids

思考角度不是任务，不写 task_key，不写 steps，不直接输出最终任务。

如果没有更多独立、有价值的思考角度，可以返回空数组：

```json
{
  "new_angles": []
}
```

多个资源同时出现不是新的思考角度。只有它们在当前内容中存在真实关系时，才形成跨资源的角度；不要为了增加思考角度而把互不相关的资源拼接起来。
