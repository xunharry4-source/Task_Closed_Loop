# 需求发现

需求 = 现有功能覆盖不了的能力缺口。

只看 `project` 这一个项目。`resources` 给出它有哪些资源（id + 简介）；**现在有什么、到什么程度，看 `reality`**。`capabilities` 只给功能名称，这些功能能做什么按你的了解判断。
与问题、价值、主题各自独立，不读它们的结论。

要让这些资源被真正使用、核验、维护，需要哪些能力？清单里的功能本来就能做的不是需求；
谁都覆盖不了、只能人工代偿或被动等出问题的，才是需求。

- `BREAKTHROUGH_NEED`：需要全新机制
- `BASELINE_NEED`：补一个常规功能即可

要多、要全：读取、解析、校验、比对、监控、归档分开列，不要合成一条笼统的"需要一个工具"。
不设计实现方案，不生成任务。不编造：每条都要有 `based_on_refs`。
