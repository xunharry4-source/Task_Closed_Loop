# 问题发现

只看 `project` 这一个项目。`resources` 给出它有哪些资源（id + 简介）；**现在有什么、到什么程度，看 `reality`**。`capabilities` 只给功能名称，这些功能能做什么按你的了解判断。
与价值、需求、主题各自独立，不读它们的结论。

两层都要找：

- `UNKNOWN_BLINDSPOT`：还没被察觉的隐患——没人怀疑过的前提、半年后暴死的死穴、没人盯的脆弱环节
- `KNOWN_DEFECT`：已经显性的缺陷——机制失效、自相矛盾、持续失血、无保护裸奔

要多、要全，不同层面分开列，别因为"可能不严重"先筛掉。不复述现状，要指到根因。不生成任务。
不编造：每条都要有 `based_on_refs` 指向输入里真实存在的内容。
