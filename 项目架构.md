# 项目架构 V0.7

## 项目定位
Task Closed-Loop Python 是接口化的 AI 主动任务闭环运行框架。

> 外部世界通过 Resource / Capability 接口进入系统；Python 负责事实结构、身份、执行记录、持久化和调用边界；LLM 负责 Current Reality 理解、Existing Task 关系判断和 Task Discovery；真实 External Effect 再回到 Reality，形成闭环。

## 总架构
```text
External Systems
  ↓
Adapters
  ↓
Resource / Capability Ports
  ↓
Provider Registry
  ├─ Resources → Reality Engine → Current Reality
  └─ Capabilities ───────────────┐
                                 ↓
Current Reality → Task Continuity → Effective Existing Tasks
                                 ↓
                         Task Generation
                                 ↓
                           0 / 1 / N Tasks
                                 ↓
                        Execution Runtime
                                 ↓
                       ActionExecutionPort
                                 ↓
                         External Effect
                                 ↓
                           Reality Engine
```

## 一级模块
### Integration Layer
- ResourceDiscoveryPort
- ResourceReadPort
- CapabilityDiscoveryPort
- ActionExecutionPort
- Provider Registry
- Provider Factory

### Adapters
具体外部系统实现自己支持的 Port。Runtime Core 不依赖 Gmail、Drive、数据库、Slack 等具体实现。

### Reality Engine
输入：Current Resources、Current Evidence、External Effects、Current Execution Deltas、Related Reality History。

输出：Current Reality。

Existing Tasks 不参与 Current Reality 的建立。

### Task Continuity
Current Reality 建立后读取 Existing Tasks，处理当前有效性、Task Identity 连续性和重复关系。

### Task Generation
输入：Current Reality、Effective Existing Tasks、Current Capabilities。

输出：0 / 1 / N Tasks。

### Execution Runtime
```text
Task → Execution Intent → Current Action Scope → Current Execution Context → Attempt → External Effect
```

External Effect 保留执行时 Target 与 Scope，并重新进入 Reality Engine。

### Information Flow Context
保留 Source、Derived Content、Handling Context、Disclosure Scope、Destination、Audience、Tenant / Customer Relation、Transformation Relation。

### Persistence
当前支持 InMemoryRepository 与 SQLite 初始化结构。

### Offline Diagnostics
- R1 Context Scope Integrity
- R2 Evidence Identity & Availability Continuity
- R3 Execution Effect Continuity
- R4 Current Execution Context Revalidation
- R5 Information Flow & Disclosure Boundary

Diagnostics 服务测试、定位和回归，不进入 Runtime 主推理链。

## 关键边界
- Resource 表示系统当前能看到什么现实。
- Capability 表示系统当前真正能做什么。
- Reality 先建立，Existing Task 后进入连续性判断。
- Task、Execution Intent、Attempt、External Effect 分别表示工作关系、逻辑执行、真实动作和真实结果。
- Runtime 负责运行，Diagnostics 负责测试与定位。
